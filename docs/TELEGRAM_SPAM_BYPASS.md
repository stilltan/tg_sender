## 1. КАК TELEGRAM ОПРЕДЕЛЯЕТ СПАМ

### 1.1 Триггеры блокировки

| Триггер | Описание | Порог |
|---------|----------|-------|
| **Одинаковые сообщения** | Один и тот же текст нескольким людям | 5-10 сообщений |
| **Скорость отправки** | Слишком много сообщений подряд | >1/мин в незнакомый чат |
| **Новые контакты** | Много ЛС незнакомцам | >40/день (новый акк) |
| **Жалобы** | Получатель нажал "Спам" | 5-7 жалоб за 24ч = бан |
| **Ссылки в первом ЛС** | Ссылка в первом сообщении | Резко повышает риск |
| **Новый аккаунт** | Молодой аккаунт без истории | CQS = 0 при регистрации |
| **Общий IP/устройство** | Несколько аккаунтов на одном IP | Каскадный бан всех |

### 1.2 Что анализирует Telegram

1. **Velocity** — скорость и плотность действий
2. **Message similarity** — схожесть текстов (n-gram анализ)
3. **Timing patterns** — равномерные интервалы = бот
4. **Account age** — молодые аккаунты под подозрением
5. **Profile completeness** — аватар, описание, имя
6. **Report rate** — жалобы получателей
7. **CQS (Contributor Quality Score)** — внутренний рейтинг аккаунта

### 1.3 Уровни ограничений

| Уровень | Что происходит | Длительность |
|---------|---------------|--------------|
| Rate limit | Flood Wait (секунды) | Секунды-минуты |
| Временный бан | Нельзя писать незнакомым | 24-48 часов |
| Spam block | Ограничение через @SpamBot | Дни-недели |
| Перманент бан | Номер в чёрном списке | Навсегда |

## 3. ОБХОДЫ И ЗАЩИТА

### 3.1 Прогрев аккаунтов (CQS)

**Новые аккаунты (CQS = 0) — самый опасный период.**

Протокол прогрева (4 недели):

```
Неделя 1-2:
  • 2-3 сообщения в день знакомым
  • Участие в группах (без ссылок!)
  • Подписка на каналы
  • Заполненный профиль (имя, аватар, описание)
  • НЕ писать незнакомым

Неделя 3-4:
  • 5-10 сообщений в день
  • Начать писать незнакомым (3-5/день)
  • Отвечать на сообщения
  • НЕ ссылки в первом ЛС

Неделя 5+:
  • 15-20 сообщений в день
  • Постепенное увеличение (+2-3 в неделю)
  • Можно ссылки (с задержкой)
```

### 3.2 Уникализация сообщений (Spintax)

**Главная причина бана — одинаковые сообщения.**

```
Привет {name}! 👋
{Вижу|Заметил|Обратил внимание}, что ты {работаешь|занимаешься|специализируешься} 
в {сфере|области|направлении} {HR|рекрутинга|подбора персонала}.
{Может|Возможно|Есть идея} {будет интересно|стоит обсудить|поговорить}?
```

Каждое сообщение должно быть уникальным на 30%+.

### 3.3 Задержки между сообщениями

```python
# ПЛОХО — равномерные интервалы (бот-детект)
for contact in contacts:
    send_message(contact)
    sleep(60)  # Всегда 60 секунд

# ХОРОШО — случайные интервалы (имитация человека)
for contact in contacts:
    send_message(contact)
    delay = random.uniform(120, 300)  # 2-5 минут
    sleep(delay)
    
    # Случайные паузы (имитация перерыва)
    if random.random() < 0.1:  # 10% шанс длинной паузы
        sleep(random.uniform(600, 1800))  # 10-30 минут
```

### 3.5 Уникальные прокси

**КРИТИЧЕСКИ ВАЖНО: один IP = каскадный бан всех аккаунтов.**

```
Правило: 1 аккаунт = 1 прокси

Типы прокси:
✅ Мобильные 4G/5G прокси (лучший вариант)
✅ Резидентные прокси
⚠️ Дата-центровые прокси (хуже, но работают)
❌ Бесплатные прокси (гарантированный бан)
```

### 3.7 Первое сообщение

**Самое опасное сообщение — первое.**

```
❌ ПЛОХО:
"Привет! Предлагаю наши услуги. Подробности: https://..."

✅ ХОРОШО:
"Привет, {name}! 👋 
Увидел твой профиль, интересно что ты делаешь в {company}. 
У меня есть пара вопросов по {теме} — можно?"
```

Правила первого сообщения:
1. НЕ ссылки в первом ЛС
2. Персонализация (имя, компания, должность)
3. Вопрос (побуждает к ответу)
4. Короткий текст (до 200 символов)
5. Без эмодзи спама

### 4.1 Что нужно добавить в tg_sender

#### A. Spintax движок
```python
import re
import random

def spintax(text: str) -> str:
    """Обработка {вариант1|вариант2|вариант3}"""
    def replace(match):
        options = match.group(1).split('|')
        return random.choice(options)
    
    while '{' in text:
        text = re.sub(r'\{([^{}]+)\}', replace, text)
    return text

# Пример:
# "Привет {name}! {Вижу|Заметил} ты {HR|рекрутер}"
# → "Привет Иван! Вижу ты рекрутер"
```

#### B. Умные задержки
```python
def get_smart_delay(account_age_days: int, messages_today: int) -> float:
    """Случайная задержка с учётом возраста аккаунта."""
    if account_age_days < 14:
        base_min, base_max = 180, 600  # 3-10 мин
    elif account_age_days < 30:
        base_min, base_max = 120, 300  # 2-5 мин
    else:
        base_min, base_max = 60, 180   # 1-3 мин
    
    # Увеличиваем задержку при большом количестве сообщений
    if messages_today > 20:
        base_min *= 1.5
        base_max *= 1.5
    
    delay = random.uniform(base_min, base_max)
    
    # 5% шанс длинной паузы (имитация перерыва)
    if random.random() < 0.05:
        delay += random.uniform(600, 1800)  # +10-30 мин
    
    return delay
```

#### D. Проверка первого сообщения
```python
def is_first_message(contact_username: str) -> bool:
    """Проверяем, писали ли мы этому контакту раньше."""
    conn = get_db()
    count = conn.execute(
        "SELECT COUNT(*) FROM message_log WHERE contact_username = ? AND status = 'sent'",
        (contact_username,)
    ).fetchone()[0]
    conn.close()
    return count == 0

def check_first_message_safe(text: str) -> tuple[bool, str]:
    """Проверка безопасности первого сообщения."""
    # Нет ссылок в первом сообщении
    if 'http' in text.lower() or 't.me/' in text.lower():
        return False, "Ссылки в первом сообщении — высокий риск бана"
    
    # Нет слишком длинного текста
    if len(text) > 300:
        return False, "Первое сообщение слишком длинное (макс 300 символов)"
    
    return True, "OK"
```

```python
async def safe_send(account, contact, template):
    # 1. Проверяем лимит аккаунта
    if account.messages_today >= get_daily_limit(account.age_days):
        return SKIP, "Лимит достигнут"

        ok, msg = check_first_message_safe(template.text)
```
